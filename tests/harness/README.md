# Testes (sem login, sem Supabase, sem npm)

Pré-requisito, uma vez: `pip install playwright` e `python -m playwright install chromium`.

## Antes de entregar, rode tudo

```
python tests/rodar-tudo.py
```

Roda sozinho todos os `tests/*.test.mjs` (no node) e todos os testes de comportamento em
`tests/harness/*.py` (no Chromium), e imprime um resumo `teste → ok/falhou`. Sai com código 1 se algum falhar,
e aí mostra a saída inteira do que quebrou. Teste novo não precisa ser inscrito em lugar nenhum: basta o
arquivo estar na pasta. O `conferir.py` fica de fora — é ferramenta, não teste.

**Em paralelo** (19/10/2026): roda **4 testes ao mesmo tempo** por padrão — o conjunto, que levava ~13 minutos um
atrás do outro (788 s em 19/10), cai pra ~4 (222 a 289 s nas três rodadas de 19/10, todas verdes). As opções:

```
python tests/rodar-tudo.py --paralelo 6    # quantos ao mesmo tempo
python tests/rodar-tudo.py --um-por-vez    # um atrás do outro, como era antes
```

A lista continua na ordem alfabética (cada linha aparece quando o teste e os de cima dele terminaram), a saída
inteira de quem falhou vem no fim e a última linha é sempre `Resumo: N testes · X ok · Y falharam` (há monitores
que leem essa linha); antes dela, a linha `Tempo:` diz quanto levou. O código de saída é o mesmo. Em paralelo, cada
teste de tela monta a cópia do site numa pasta só dele, `.harness/site-<nome do teste>`, apagada no fim — o
`montar_site()` do `conferir.py` usa a pasta da variável de ambiente `HARNESS_SITE` (sempre dentro de `.harness/`)
e, sem ela, a `.harness/site` de sempre. Os mais demorados começam primeiro, pelo tempo da última vez
(`.harness/tempos-dos-testes.json`). Teste que só passa sozinho entra na lista `SOZINHOS` do `rodar-tudo.py`
(roda depois dos outros, um por vez) — antes disso, troque a espera fixa (`wait_for_timeout`) por esperar a
condição (`wait_for_function`, `wait_for_selector`).

## Fotografar telas (ferramenta)

```
python tests/harness/conferir.py fiscal-reforma.html comercial-precificacao.html
```

Fotografa cada tela nos temas escuro e claro em `.harness/fotos/` e lista os erros de JavaScript.
Serve pra conferir à vista e pra provar que uma mudança não mexeu no visual (fotografe antes e depois e
compare pixel a pixel). Detalhes do trabalho de tema: `docs/TEMA-CLARO-CODE.md`.

## O banco falso

`supabase.mock.js` entra no lugar de `assets/js/supabase.js` na cópia do site (`.harness/site`, fora do git).
Os dados são todos inventados — **nada de cliente**, que este repositório é público. Dá pra acrescentar dados
inventados quando um teste precisar; os testes leem o banco falso por `window.__mockDb`.

Como o assistente do escritório aparece em todas as telas com login, o mock deixa quietos os recados do dia dele
(a saudação e o recado de cada tela) pra não cobrir o que os outros testes clicam; quem testa os recados liga com
`window.__assistenteRecados = true` (`assistente-escritorio.py`, `reforma-chat.py`).

Quem está logado é o Samuel (sócio); o teste troca por `window.__mockEmail` (o `precificacao-carteira.py` entra como a
Thalia). O `upsert` do banco falso segue o de verdade: com `ignoreDuplicates`, a linha que já existe (pelo `onConflict`)
fica como está; sem ele, é atualizada.
